### A2. Audit Arsitektur Reverse Proxy Eksisting & Mekanisme OsmAnd Backend

Audit kode sumber Java backend pada [`traccar/src/main/java/org/traccar/web/WebServer.java`](file:///c:/Users/hkur7/Documents/development/GPS%20Project/traccar/src/main/java/org/traccar/web/WebServer.java#L113-L129) dan referensi panduan deployment [`Panduan Hosting VPS dan Integrasi REST API Traccar.md`](file:///c:/Users/hkur7/Documents/development/GPS%20Project/Panduan%20Hosting%20VPS%20dan%20Integrasi%20REST%20API%20Traccar.md#L192-L230) mengungkap fakta arsitektural kunci:

1. **Traccar Built-in Client Proxy (`WebServer.java#L113-L129`):**  
   Jetty WebServer bawaan Traccar (port `8082`) **sudah memasang** `AsyncProxyServlet.Transparent` (`/client-proxy/*` $\rightarrow$ `http://localhost:5055`) disertai servlet filter yang otomatis meneruskan setiap permintaan **`POST /`** ke listener internal OsmAnd (`localhost:5055`).
2. **Nginx TLS Reverse Proxy Produksi Eksisting:**  
   Panduan VPS proyek sudah mendefinisikan blok Nginx standar (`https://gps.domainanda.com/` $\rightarrow$ `http://127.0.0.1:8082`). Karena `location /` mem-proxy seluruh root path termasuk `POST /` dan UFW tidak membuka port `5055` (`ufw allow 22, 80, 443, 8082, 5023, 5022, 5013`), server produksi sebenarnya sudah mendukung ingestion OsmAnd terenkripsi HTTPS melalui **`POST https://gps.domainanda.com/`** persis seperti yang dilakukan `traccar-web/src/other/EmulatorPage.jsx#L81-L92`!
3. **Dekoder OsmAnd Mendukung Form Body & Query Params (`OsmAndProtocolDecoder.java#L82-L87`):**  
   Jika URI query parameter kosong, `OsmAndProtocolDecoder` otomatis mem-parsing body `request.content()` (`application/x-www-form-urlencoded`).

| :--- | :--- | :--- | :--- |

## 3. Stage B — Rencana Implementasi Teknis

### B1. Komunikasi OsmAnd Aman & Kompatibel Produksi

Strategi pemilihan endpoint OsmAnd pada `AppConfig` dan `TelemetryEmulatorRemoteDataSourceImpl` ditingkatkan menjadi **Scheme-Aware Transport Resolution** (dengan tetap menjaga 100% kompatibilitas kontrak `OsmAndProtocolDecoder.java` dan `WebServer.java`):

1. **Mode 1 — HTTPS Proxy (`appConfig.baseUrl` berskema `https://` tanpa override `customPort`):**
   - **Target URI:** `POST {baseUrlOrigin}/` (misal `POST https://gps.domainanda.com/`).
   - **Format Payload:** Header `Content-Type: application/x-www-form-urlencoded` dengan body URL-encoded dari `packet.toOsmAndParams()` (`packet.toQueryString()`), **tanpa** menaruh koordinat sensitif/IMEI di query string URL (selaras dengan `EmulatorPage.jsx#L86-L92`).
   - **Probing (`probeOsmandPort`):** Mengirim `POST {baseUrlOrigin}/` dengan body `id=probe_ping` (`application/x-www-form-urlencoded`). HTTP `200` atau `400` menandakan Nginx HTTPS + Jetty `WebServer.initClientProxy` (`WebServer.java#L122`) + internal OsmAnd `5055` beroperasi aktif; `405`/`404`/`502`/timeout/network error dianggap tidak terjangkau.
   - **Keamanan:** **100% TLS (Port 443)**. Tidak memerlukan pengecualian cleartext pada Android Release `network_security_config.xml`, tidak melemahkan iOS ATS, dan tidak memerlukan pembukaan port `5055` pada firewall VPS.
2. **Mode 2 — Direct HTTP Port 5055 (`appConfig.baseUrl` berskema `http://` atau saat `customPort` eksplisit diberikan):**
   - **Target URI:** `http://{host}:{port}/?{params}` (`defaultPort = 5055`), sesuai standar Netty `TrackerServer` untuk dev lokal (`10.0.2.2:5055`, `localhost:5055`, LAN debug IP).
   - **Opsional Proxy HTTP Fallback (Dev/Docker Convenience):** Bila `appConfig.baseUrl` berskema `http://`, `customPort == null`, dan permintaan ke port `5055` gagal koneksi (`Connection Refused` seperti pada `docker-compose.yml` standar yang hanya membuka port `8082` ke host!), `TelemetryEmulatorRemoteDataSourceImpl` (atau melalui parameter/opsi `allowWebProxyFallback = true`) dapat mencoba **`POST http://{host}:{baseUrlPort}/`** melalui `WebServer.initClientProxy` port `8082`! Dengan demikian, baik Traccar yang membuka port `5055` maupun Docker Compose standar yang hanya membuka port `8082` dapat diuji mulus tanpa memodifikasi `docker-compose.yml` atau backend! *(Catatan: Jika `customHost` atau `customPort` diberikan secara eksplisit, tidak melakukan fallback diam-diam agar error uji konfigurasi kustom tetap transparan.)*
3. **Konfigurasi Platform Tetap Ketat:**
   - Pertahankan konfigurasi aman Android (`release` hanya `https://` + loopback `10.0.2.2`/`localhost`/`127.0.0.1`; `debug` mengizinkan HTTP LAN) dan iOS (`NSAllowsLocalNetworking = true`).


**Aturan Implementasi B2:**

### B3. Integrasi Map Tap Coordinate Injection (`FleetMapWidget.onMapClick`)

```
Mode Pilih Peta OFF (Default Pelacakan Normal):
  User tap peta ──> FleetShellScreen._onMapClick ──> Diabaikan untuk emulator
  User tap marker ──> FleetMarkerManager.onMarkerTapped ──> Pilih armada & VehicleDetailSheet

Mode Pilih Peta ON (Diaktifkan dari Mode Pengembang atau Tombol "Pilih di Peta" Sheet):
  FleetShellScreen menampilkan Floating HUD Card "Mode Pilih Koordinat Emulator"
  User tap titik di peta (Point, LatLng)
    ├── 1. Validasi: CameraCalculationHelper.isValidCoordinate(lat, lon)
    │      (Jika NaN/Infinite/(0,0)/out-of-bounds -> tampilkan SnackBar peringatan ringan, abaikan)
    ├── 2. Injeksi ke state: telemetryEmulator.setMapPickedCoordinates(lat, lon)
    │      (TIDAK MEMANGGIL sendSingleFix()!)
    ├── 3. Floating HUD diperbarui real-time menampilkan:
    │      - Target Device + Unique ID (atau prompt kuning "Belum ada kendaraan target" + tombol "Pilih Unit")
    │      - Koordinat terpilih: "Lat: -6.208800, Lon: 106.845600"
    │      - Tombol Aksi Eksplisit:
    │          [Kirim Titik Ini] (hanya aktif & memanggil sendSingleFix() jika targetUniqueId tidak kosong)
    │          [Panel Lengkap]   (membuka TelemetryEmulatorSheet berisi koordinat yang baru diketuk)
    │          [Selesai]         (mengembalikan isMapPickMode = false)
    └── 4. PopScope: Tekan Back saat isMapPickMode == true -> menutup Mode Pilih Peta lebih dulu.
```

**Penanganan Kasus Khusus yang Diwajibkan B3:**
1. **Tidak ada auto-transmit:** Mengetuk peta hanya memanggil `setMapPickedCoordinates(lat, lon)`. Paket HTTP hanya dikirim saat tombol `"Kirim Titik Ini"` atau `"Kirim Titik Tunggal"` atau `"Mulai"` simulasi ditekan eksplisit.
2. **Saat target device belum dipilih:** Pengetukan peta tetap menyimpan preview koordinat di provider dan menampilkannya di HUD dengan badge peringatan *"Pilih kendaraan target dahulu untuk mengirim titik"*. Tombol kirim di HUD memunculkan SnackBar/mengarahkan membuka `TelemetryEmulatorSheet` untuk memilih unit target dari dropdown.
3. **Saat `TelemetryEmulatorSheet` sudah terbuka:** Menambahkan tombol `"Pilih di Peta"` (`emulator_pick_on_map_button`) pada bagian Koordinat sheet. Mengetuknya mengaktifkan `isMapPickMode = true` dan menutup modal sheet (`Navigator.pop`) agar kanvas peta tidak tertutup backdrop gelap modal. Setelah mengetuk peta, pengguna menekan `"Panel Lengkap"` untuk membuka sheet kembali yang otomatis tersinkron ke koordinat ketukan terakhir.
4. **Kompatibilitas Marker & Gestur Peta:** `onSymbolTapped` pada `FleetMarkerManager` tetap independen. Jika sebuah marker armada sedang terpilih (`selectedDevice != null`) dan user mengetuk peta saat `isMapPickMode == false`, tidak ada interaksi emulator yang terpicu; saat `isMapPickMode == true`, HUD mengambang terpisah dari `VehicleDetailSheet` (atau menunda buka sheet agar tidak saling tumpang tindih).
